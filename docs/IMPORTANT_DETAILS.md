# 最容易遗漏的细节
1. 幂等读取也要鉴权，否则可借已知command_id读取别人结果。
2. session_epoch属于连接权限；owner_epoch属于房间写入权限；state_version属于局内事件顺序。三者不能混用。
3. 新连接重试旧command不更换command_id；hash排除session_epoch但包含原expected_version。
4. 成功ACK与目前快照不是同一个对象，重放结果不能回退UI。
5. 房间锁住状态不应等待socket写入；有界队列与写超时是必要配套。
6. timeout也是业务事件，与action竞争同一回合版本。计时器唤醒不是时间事实。
7. 获取锁后再读取DB时钟；不能用等待锁之前的陈旧时间批准行动。
8. commit未知不能直接重做新请求；按原command查询。
9. 内存状态失败后不能比DB超前；广播只能引用已提交状态。
10. Redis投影必须原子地比较版本并替换绝对值；分开的GET/SET仍有竞态。
11. 匹配房间不ready必须回收占用；终局释放占用前确认结果持久化，允许结算异步完成。
12. aborted不是finished；恢复失败不能捏造赢家。
13. 评分窗口有冷门玩家饥饿问题；观察分布，不只平均值。
14. 恢复后跨过多个deadline不等于补打几十个回合；执行规范约定。
15. 对应用进程崩溃的保证不自动涵盖数据库主从切换或磁盘损坏。
16. 损坏快照有校验和，但校验和不能提供丢失数据；要有可用事件或备份。
17. bot也是程序，可能CPU/连接先饱和；必须一起采集。
18. 每一步落库适合低频回合制；不能宣称该方案适用于所有实时游戏。
