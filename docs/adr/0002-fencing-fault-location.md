# ADR 0002：区分租约 fencing 与悬挂数据库事务

实测：首次WSL参考验收中，Lab07 fenced-zombie-owner 在5秒等待窗口失败；abort分支通过。暂停可能命中心跳的SELECT FOR UPDATE与提交之间，使数据库行锁保持占用。租约过期不解除行锁。

原固定场景未声明暂停位置，混合了两种故障。现将 `pause_owner` 明确为：测试控制端等待正在进行的维护事务完成、暂停后续维护，然后真实SIGSTOP。新节点正常等待租约到期、增加epoch；SIGCONT恢复旧进程，再验证旧epoch被拒绝。期望版本和计分断言不变。

这仅验证 fencing，不证明任意指令处SIGSTOP后5秒内恢复。任意事务位置暂停需独立实验，观察锁等待和连接超时，并明确数据库断开旧连接策略。不得将该Gate的耗时当成生产RTO。

这是故障注入位置澄清，不是让driver模拟节点切换：真实子进程仍停止，租约和epoch仍由服务与MySQL推进。任意位置暂停实验完成前，该恢复场景标记未覆盖。
